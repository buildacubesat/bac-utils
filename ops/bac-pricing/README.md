# bac-pricing v1.4.1

Build a CubeSat – assembly pricing. A multi-level bill of materials is rolled up from its quoted parts through landed cost, consumables and labour to a fully loaded batch cost, and the price that recovers it at the target margin is derived through the batch waterfall (zero-revenue units, discount tiers, regional markets). A pure Python engine does the computation; a marimo notebook is the UI over it; the pricing engine of the business operations suite keeps the data in PostgreSQL (or in files, before a database exists). Regression anchor: the Dev Kit v1 at batch 25 prices at CHF 1'138 with a 20 % margin.

Part of the `ops/` suite – see [`ops/README.md`](../README.md) for the suite, [`lib/bac-suite-db`](../../lib/bac-suite-db/) for the shared layer and `bac-db`. The data model is documented in `SCHEMA.md`.

## 1. Install

```sh
uv tool install ./ops/bac-pricing       # from the bac-utils checkout
bac-pricing --init                      # once: backend, data directory, DSN (shared with every suite tool)
bac-pricing                             # opens the notebook in marimo's editor
bac-pricing --app --port 2719           # serves it as an app (code hidden; saving still works)
```

Inside the checkout, `uv run bac-pricing`. The launcher resolves the suite settings, fails early with a clear message when the config or the DSN is missing, prints backend, data directory and database (host and name only), and starts `marimo edit` or, with `--app`, `marimo run` (the code hidden, the controls and the Save buttons live) on the notebook, which lives inside the package (`bac_pricing/notebook.py`). `--dry-run` shows the command instead; `--headless` keeps the browser closed; `--host` other than localhost prints a warning, because marimo has no authentication.

## 2. Data

Five files make a data set, with an optional sixth; `examples/` holds Build a CubeSat's own numbers as of 2026-07-06 (published deliberately – `salary_monthly` in the config is the documented labour-cost parameter, not a payroll figure) and is the set to copy into your data directory:

| File | Holds |
| :-- | :-- |
| `bac-items.csv` | Every BOM node: `item_id`, SKU, name, type (assembly, subassembly, part, service), category, vendor, customs fields, unit, sellable, domain |
| `bac-bom.csv` | Parent→child edges with the quantity per parent and the labour minutes and consumables this usage costs; `consumables_<base>` carries the base-currency suffix |
| `bac-price-breaks.csv` | Vendor quantity-price breaks in the vendor's currency |
| `bac-price-overrides.csv` | Manual per-item cost overrides (absolute, factor, additive – with the suffix) and per-item rounding |
| `bac-pricing-config.toml` | Vendors with their overhead factors, discount tiers, regions, financials, FX rates, rounding, batch disposition |
| `bac-catalog.csv` | Optional. Customs and shipping attributes per sellable SKU for the shared catalog (HS code, legal country of origin, customs description, …) |

`bac-db import pricing DIR` validates the set – every edge and vendor resolves, no negative quantities, the BOM is acyclic, every SKU follows the scheme, every sellable item has one – and loads it; `bac-db export pricing DIR` writes it back from the database in the same layout and column order, notes included, sorted by key – so the first export of a hand-ordered file is a reordering diff, and every export after that is stable. In files mode the notebook reads and writes the data directory directly. SKUs follow the Tooling Guide's scheme (`bac-dev-kit-2u-v1r1`); the three in the example data were migrated from the earlier `BAC-HW-KIT-0001-R1` form in 1.4.0.

## 3. The notebook

One control panel: assembly, batch size, target margin and the batch composition in two columns, with Settings (base currency, markets and FX, market roles, financial assumptions, discounts and rounding, vendors) and Storage (status, Save data, Save config, backup) as accordions. Below it: Headline Numbers (primary and secondary market price, assembly cost, domestic price incl. VAT, realised margin, operating profit), Batch Economics, the Checks callouts (unpriceable composition, data problems, FX sync, quotes pending, higher-bracket fallback), three charts (price against batch size, the batch × margin price landscape, the cost breakdown by subsystem, cost type or vendor), the regional price table, the price list, the BOM editor in its two views and the price-break editor.

Save data replaces the BOM, price breaks and overrides (the three `pricing.*` tables, or the three CSVs in files mode); Save config appends a new `pricing.params` version (or rewrites the TOML). Backup writes a snapshot under `<data_dir>/backups/<timestamp>/` first. Every number is a modeled cost from quotes, factors and assumptions – items without a quote contribute nothing and the rollup is a lower bound until they are priced.

Two network calls: the fonts come from Google Fonts, and Sync FX fetches rates against the base currency from frankfurter.dev (and its currency list, to flag codes it does not know). Everything else is local.

## 4. The engine

`bac_pricing.engine` is importable and has no storage opinions: `load_model(dir)`, `validate_model(model)`, `rollup(model, root, batch)`, `derive_root_price(model, rollup)`, `price_list(model, batch)`, `regional_prices(model, base_price, domestic)`, `rebase_fx()`, `sync_fx()`, `dump_config(cfg)`. The cost chain:

```
base       = unit_price × fx × qty                    per leaf, summed
+ shipping = base × (ship_factor – 1)
+ bank     = base × ship × (bank_factor – 1)
+ duties   = base × ship × bank × (duties_factor – 1)
= landed materials
+ consumables (per edge, per parent instance, per unit of root)
+ labour (minutes → person-days → base currency via salary)
= direct cost
× expense_safety × overhead_safety
= total recoverable cost
```

The root price: `target_revenue = total / (1 – margin)`; at-cost tiers contribute their units at the nonprofit basis cost, percentage tiers `units × (1 – value) × P`, full-price units `units × P`; `P` solves the equation. A composition with no revenue-bearing units left is flagged as unpriceable rather than priced negative. Other sellable items take `cost / (1 – margin)`. `bac_pricing.store` holds the engine's tables, the import and export, the files-mode save, the base-currency switch and `primary_price_factor()`.

## 5. Tests

```sh
uv run pytest ops/bac-pricing
BAC_TEST_DSN=postgresql://postgres@localhost/bac_test uv run pytest ops/bac-pricing/tests/test_live.py
```

`tests/fixtures/` is a frozen copy of the data set (the regression anchor), separate from `examples/` so the shipped numbers can change without moving the tests. The engine tests are the parity suite of 1.3.0; the store tests run on `bac_suite_db.testing.FakeConn`; the notebook runs headless in both modes; the live tests need `BAC_TEST_DSN` naming a database with `test` in its name (they drop the schemas).

## 6. Adapting for your own project

Copy `examples/` to your data directory and edit: your items, BOM edges, quotes and the config (vendors, tiers, regions, financials). Keep the base-currency suffix on the cost columns in step with `base_currency`; the notebook's base-currency switch does that for you. The notebook binds its two tier controls to the first `percentage` and the first `at_cost` tier by kind, whatever they are called, and defaults the market roles to `US`, `EU` and `CH` where those labels exist, else to the first market; no number in the package is Build a CubeSat's.
