# bac-update-content-plan v0.4.0

Build a CubeSat – renders the content plan, which lives in a Google Sheet, as one Markdown table into the docs repository and, on request, commits and pushes it. The sheet stays the place where the plan is edited; the file is a generated view of it that the documentation site publishes.

## 1. Install

```sh
uv tool install ./tools/bac-update-content-plan     # from the bac-utils checkout
bac-update-content-plan --init
```

`--init` asks for the spreadsheet (id or URL), the docs repository and the file inside it, and writes `~/.config/bac/bac-update-content-plan.toml`. The service-account key is a secret and is not stored there: put `BAC_GCP_CREDENTIALS=/path/to/key.json` in a `.env` file in the directory you run the tool from (or above it), or pass one with `--env-file`; `.env.example` shows the line. Share the sheet with the key's `client_email` as you would with a person, or the API answers 403 – the error then names the address to share with.

## 2. Usage

```
bac-update-content-plan [--dry-run] [--commit | --push [-y]] [-m TEXT]
                        [--env-file PATH] [--config PATH]
```

A run reads the configured range, keeps the rows that have a value in the status column, writes the table, and prints how many rows came in, how many were written and how many lines of the file changed. `--commit` stages and commits the file on the configured branch; `--push` commits and then pushes after asking (`-y` answers yes, for a cron job or a script; without a terminal the push is skipped with a note). `-m TEXT` sets the commit message; the default is `Update content plan`.

Before anything is fetched or written, the repository is checked: it must be an existing git work tree (so a typo in the configured path cannot become a new directory tree), and with `--commit` the branch must exist and, when another branch is checked out, the tool switches first – a local edit that conflicts with the switch makes git refuse, and then nothing has been written. The commit contains the content plan file only; anything else staged in the repository stays staged. `--dry-run` fetches and renders, compares against the file on the configured branch, reports `Would write` / `Would commit`, and changes nothing.

Exit codes: `0` done, also when the file is unchanged and there is nothing to commit; `1` the sheet, the key, the config or git refused (the message says which, with the next step); `2` bad arguments.

## 3. Output shape

```markdown
<!-- Generated by bac-update-content-plan from https://docs.google.com/spreadsheets/d/…/edit – edit the sheet, not this file. -->
# Content Plan

| Title | Channel | Status | Notes |
| --- | --- | --- | --- |
| Why a 1U \| not a 3U | YouTube | draft | line one line two |
| EPS walkthrough | YouTube | published |  |
```

The first row of the range is the header. Rows that are empty in every cell are left out; when the header has the configured status column (`Status` by default), rows with an empty value there are left out too – the sheet's drafts and placeholders. A pipe inside a cell is escaped, line breaks inside a cell become spaces, short rows are padded to the header's width. The comment on the first line tells the next reader where the content comes from; MkDocs does not render it.

## 4. Configuration

`--init` writes:

```toml
# bac-update-content-plan.toml
[sheet]
id = "1AbCdEfG…cdefg"          # spreadsheet id (the part between /d/ and /edit in its URL)
range = "'Content Plan'!A:E"    # A1 range; the first row is the table header
title = "Content Plan"          # Markdown H1 above the table
status_column = "Status"        # rows with an empty cell in this column are left out; "" keeps every row

[output]
repo = "~/bac/bac-docs"         # git work tree the file is written into
file = "content/content-plan.md"   # relative to repo
branch = "main"
remote = "origin"

[credentials]
file = ""   # service-account JSON key; BAC_GCP_CREDENTIALS overrides this
```

`sheet.id` accepts the full URL as well. `output.file` must stay inside the repository. The key path comes from `BAC_GCP_CREDENTIALS` first and `[credentials] file` second, so a machine where the key always sits in one place can name it in the config and skip the `.env`.

## 5. Adapting for your own project

Nothing in the tool is specific to Build a CubeSat except the defaults `--init` offers. Point `[sheet]` at any spreadsheet a service account can read, `[output]` at any git repository, and set `status_column` to the column that marks a row as ready – or to `""` to publish every row. The Sheets reader is `bac_common.gsheets` and is shared with other tools: `SheetsClient.from_service_account(key).read_range(id, "'Tab'!A:E")` returns rows of strings.
